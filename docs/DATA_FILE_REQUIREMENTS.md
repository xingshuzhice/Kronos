## 🔍 如何检查数据文件

### 使用 head 命令查看文件头
```bash
head -1 /path/to/your/file.csv
# 显示列名
head -2 /path/to/your/file.csv
# 显示第一条数据的时间
tail -1 /path/to/your/file.csv
# 显示最后一条数据的时间
```

### 使用 wc 命令检查行数
```bash
wc -l /path/to/your/file.csv
# 显示总行数（包括表头）
```

### 示例
```bash
$ head -1 btc.csv
timestamps,open,high,low,close,volume

$ head -2 btc.csv | tail -1
2025-08-31 01:00:00,109341.2,109349.9,109086.0,109094.1,427.9305

$ wc -l btc.csv
401
```

## 📈 时间滑块工作原理

### 工作流程
```
用户拖动时间滑块
    ↓
选择 start_date = "2025-08-28"
    ↓
后端检查：
  1. 数据是否从 2025-08-28 开始？
     → btc.csv 从 2025-08-31 开始 ❌
  2. 从 2025-08-28 有 520+ 个数据点？
     → btc.csv 根本没有 2025-08-28 的数据 ❌
    ↓
返回错误：
  "选择的起始时间 (2025-08-28) 早于数据的最早时间 (2025-08-31)"
```

### 时间滑块限制
时间滑块的 start_date 必须满足：

```
start_date >= data_first_timestamp
AND
(data_last_timestamp - start_date) >= (lookback + pred_len)
```

对于 btc.csv：
```
start_date >= 2025-08-31 01:00:00  ← 第一个条件
(data_end - start_date) >= 520      ← 第二个条件

所以有效的 start_date 范围：
最早: 2025-08-31 01:00:00
最晚: 2025-08-31 后面（取决于数据结束时间）
```

## ⚠️ 常见错误

### 错误 1：时间太早
```
❌ 选择了 2025-08-28，但数据从 2025-08-31 开始
→ 错误信息：起始时间早于数据的最早时间

解决：选择 2025-08-31 或更晚
```

### 错误 2：数据不足
```
❌ 选择了一个时间，但从那时起数据不足 520 行
→ 错误信息：数据不足，需要至少 520 个数据点

解决：选择更早的时间，或使用更大的数据文件
```

### 错误 3：数据太小
```
❌ 只有 400 行数据，无法满足 520 行的需求
→ 错误信息：数据不足

解决：
  - 方案 1：不使用时间滑块，使用"最新数据"模式
  - 方案 2：换更大的数据文件
```
