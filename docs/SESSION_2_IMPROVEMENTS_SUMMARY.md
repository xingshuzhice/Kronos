## 🔍 问题分析

### 根本原因假设

基于代码审查，最可能的原因（按概率排序）：

#### 1. **时间滑块 DOM 状态被修改** (50% 概率)
```
症状：第二次预测时 startPercentage 计算错误
原因：Plotly.newPlot() 可能导致 DOM 重排
影响范围：start-handle 元素的 style.left 属性
```

#### 2. **sliderData 对象被污染** (30% 概率)
```
症状：第二次预测时 sliderData 为 null 或数据不正确
原因：全局变量被无意修改
影响范围：initializeTimeWindowSlider() 的结果
```

#### 3. **时间戳格式不一致** (15% 概率)
```
症状：start_date 格式不同导致后端验证失败
原因：toISOString().slice(0, 16) 在不同预测中返回不同结果
影响范围：后端的 pd.to_datetime() 处理
```

#### 4. **后端状态污染** (5% 概率)
```
症状：前端参数正确但后端返回 400
原因：全局变量 predictor/model/tokenizer 被损坏
影响范围：第二次预测请求
```

**修复代码框架**：

```javascript
function displayPredictionResult(result) {
    // 保存滑块状态
    const savedSliderState = {
        startHandle: document.getElementById('start-handle').style.left,
        endHandle: document.getElementById('end-handle').style.left
    };

    // 显示图表
    const chartData = JSON.parse(result.chart);
    Plotly.newPlot('chart', chartData.data, chartData.layout);

    // 恢复滑块状态
    document.getElementById('start-handle').style.left = savedSliderState.startHandle;
    document.getElementById('end-handle').style.left = savedSliderState.endHandle;
}
```

## 🎓 学到的教训

### 问题诊断的关键

1. **添加详细的中间过程日志** → 能追踪状态变化
2. **保留历史数据** → 能对比第一次和第二次的差异
3. **标准化错误信息** → 能快速识别问题类型
4. **提供修复方案** → 能自助解决问题

### 防止类似问题

1. **全局变量保护** → 使用 Proxy 或常量
2. **DOM 状态保存** → 在修改前保存，修改后恢复
3. **单元测试** → 重复操作测试
4. **集成测试** → 模拟用户场景
